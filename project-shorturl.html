NEXON Shortened URL · AI 협업형 PRD 재구축

넥슨코리아 · 2026.03 — 진행중
AXFigma AIPlatform
레거시 사내 단축 URL 서비스를 사용성·운영성·확장성 관점에서 전면 재설계. Speckit 기반 협업형 PRD 워크플로우를 정립해 기획·개발 명세를 단일 문서로 통합하고, 그 명세가 곧 개발·검증의 기준이 되도록 구조화.
문제 인식

PRD가 사람의 합의서로 끝나면, 기획·개발·AI는 같은 문서를 보고도 서로 다른 결과를 만듭니다.

  • 명세 단절 — 기획자의 PRD, 개발자의 스펙 문서, AI 프롬프트가 각각 다른 형식으로 존재해 정보 누락·해석 편차 발생
  • 모호성 = 결과 편차 — 명세에 빈틈이 있으면 사람도 AI도 각자 추정해 메우게 되어 결과물 일관성 저하
  • 운영 사고 리스크 — 기존 단축 URL 서비스의 3자리 정책으로 브라우저 캐시 대소문자 충돌 발생(n8G → 캐시 n8g → 신규 N8g와 충돌)
  • 권한 구조 의존성 — 슈퍼어드민 개념으로 인계자가 타인 링크 수정 불가, 운영 인계 시마다 공수 발생
프로젝트 목표

"명세를 구조화하면, 기획·개발·AI가 같은 결과를 만든다."

Speckit 기반 협업형 PRD를 통해 Consistency · Co-authoring · Compactness · Continuity 네 가지 핵심 가치 달성.

COMPACTNESS

CONTINUITY

AI LAB 핵심 기획 의사결정

NEXON Shortened URL은 단순 리뉴얼이 아닙니다. Speckit 기반 협업형 PRD로 기획·개발 명세를 단일 문서로 통합한 결과, 운영 사고를 원천 차단하는 정책 의사결정들이 PRD 단계에서 모두 이뤄졌습니다.

1

코드 정책 재설계 — Base36 7자리

브라우저 캐시 대소문자 정규화로 인한 충돌 사례를 PRD 단계에서 정의하고, Bitly · TinyURL · Short.io · t.co의 코드 정책을 벤치마킹해 Base36(소문자+숫자) 7자리로 전환했습니다. 783억 코드 공간을 확보하면서도 캐시 충돌 가능성을 0으로 만들었습니다. 서버 입력 단계의 toLowerCase() 정규화까지 PRD에 명시해 정책이 코드에 정확히 이식되도록 했습니다.

2

권한 모델 평탄화 — 어드민 개념 제거

슈퍼어드민 권한 분기를 삭제하고, 난수 7자리 코드 인증 + 사번 자동 로깅 기반의 평탄한 권한 모델로 재설계했습니다. 본인·타인 구분 없이 누구나 수정 가능하되, 변경 이력은 시스템이 자동으로 추적합니다. 인계 시마다 발생하던 권한 이양 공수가 사라졌습니다.

3

만료 일자 단일 API 통합

만료 전 연장과 만료 후 재활성화를 별도 기능으로 두지 않고, 시작일·종료일 변경 단일 수정 API로 통합했습니다. 730일 상한 검증을 백엔드에 일원화하고, 시작일을 변경하면 종료일 상한도 자동 재계산되도록 설계했습니다. 추가 API 없이 모든 케이스를 처리할 수 있는 컴팩트한 구조를 확보했습니다.

4

도메인 운영 표준화

기존 하드코딩된 도메인 운영을 제공 가능한 도메인 리스트를 드롭다운으로 표기했고, 추가 희망 시 요청 프로세스를 표준화했습니다.

AI 워크플로우 인사이트 — AI 시대의 협업형 PRD
  • 역할 분담 + 병합 — 한 사람이 PRD를 처음부터 끝까지 쓰는 방식이 아니라, 기획자(서비스 플로우·유즈케이스)와 개발자(개발 스펙·아키텍처)가 초안을 병렬 작성한 뒤 단일 PRD로 병합합니다. 각자의 전문성을 잃지 않으면서 단일 문서 체계 안에서 연결되는 구조입니다.
  • Speckit으로 정합성 확보 — 두 초안을 그대로 합치면 형식·용어·디테일 수준이 달라 충돌이 납니다. Speckit으로 요구사항·스펙을 일관된 형식으로 구조화해 모호성과 누락 항목을 자동 검출하고, 두 문서가 같은 언어로 정렬되도록 정제했습니다.
  • Figma AI로 명세 → 화면 즉시 검증 — 정제된 PRD를 기반으로 Figma AI를 활용해 프론트엔드 화면을 빠르게 생성합니다. 명세에서 빠진 인터랙션·예외 케이스가 화면 단계에서 즉시 발견되어, PRD ↔ 화면 양방향 검증 루프가 작동합니다.
  • 기준 문서로서의 PRD — 병합된 PRD가 단순 설명 문서가 아니라, 개발·QA·일정 논의에 그대로 활용 가능한 기준 문서 역할을 합니다. 이 워크플로우는 후속 프로젝트의 표준 협업 방식으로 확장 가능한 자산이 됩니다.
AS-IS · TO-BE 요약 (사내 서비스로 화면 제공 불가)
AS-IS · 기존
  • 3자리 난수(대·소문자 혼용) 정책으로 브라우저 캐시 정규화 시 의도치 않은 리다이렉트 충돌 가능
  • 슈퍼어드민 권한 분기에 의존 — 타인 링크 수정·운영 인계 시마다 반복 공수
  • 도메인 단일·예외 하드코딩 위주
  • 만료 일자 UX·알림 부족, 통계는 로우 데이터 중심
TO-BE · 리뉴얼
  • Base36 7자리(소문자+숫자) + 서버 단 정규화로 캐시 충돌 가능성 제거 및 코드 공간 확보
  • 난수 코드 인증 + 사번·변경 로그 기반 평탄한 권한 모델(슈퍼어드민 개념 제거)
  • 제공 도메인 드롭다운·추가 요청 프로세스 표준화
  • 만료 프리셋·재활성화·QR·운영 지표 확장
Reflection

명세의 모호성을 줄이는 일이 곧 협업의 속도를 만든다. AI 시대의 PRD는 사람뿐 아니라 AI도 함께 읽는 문서다.
